# Phase 13 Gaussian / Acuity Calibration

從 Simulator → Settings → Gaussian / Acuity Calibration 進入，或開啟 `/acuity-calibration/`。它與主畫面共用 53.98 mm 信用卡短邊校正及儲存格式。校準工具的刺激固定以眼睛至螢幕 40 cm 計算，校正卡片比例時保留主模擬器原本的觀看距離。舊版校正可繼續供主畫面使用。首次使用本工具時，舊校正若缺 DPR 記錄，須再比對信用卡一次。

校正線超過手機可用寬度時會自動轉為垂直，仍比對信用卡短邊。測量工具也會依裝置限制實際可顯示的校正線長度。

## 幾何與取樣

Landolt C 為黑色平面環，內徑為外徑的 3/5，環寬與缺口均為外徑的 1/5，缺口獨立隨機選自八個方位。每像素以 4 × 4 子樣本積分覆蓋率。幾何、取樣與紀錄設計參考同工作區智慧眼鏡專案的唯讀 `research-local` 分支（`a42573e`）。 [ISO 8596:2017](https://www.iso.org/standard/69042.html)

- `MAR′ = 10^logMAR`，外徑視角為 `5 MAR′`。以 `D = 400 mm` 和角分轉弧度後的外徑角 `θ` 計算平面外徑 `2D tan(θ/2)`。環寬與缺口在平面均為外徑的 1/5。0.0 logMAR 的外徑約 0.582 mm，缺口約 0.116 mm。
- 保存匹配卡片短邊時的 CSS px/mm、viewport zoom 與 DPR。有效 CSS px/mm 為 `校正 CSS px/mm × 校正 zoom / 目前 zoom × 校正 DPR / 目前 DPR`。刺激 backing store 與 CSS 尺寸比例為 `目前 DPR × 目前 zoom`，由此求出 rendering px/mm。此補償假設同一螢幕，換裝置或外接螢幕後請重新校正。
- σ 為等向 Gaussian 在各軸的切平面角標準差。 `σrender = σarcmin × π/10800 × 400 × rendering px/mm`。尺寸調整只改變 C 的幾何，固定 σ 得到相同的渲染 σ。共用取樣核的權重為 `exp(−x²/(2σ²))` 並正規化。校準頁以 ±4σ 截斷，分離卷積水平與垂直的顯示編碼值，沿用主場景 Gaussian 對編碼值進行卷積的定義。
- 缺口低於 2 px 時停用量測。非零 σ 必須至少為 0.75 rendering px，以 0.25 arcmin 為步進，最大 12 arcmin。最大畫布為 512 px 方形，顯示空間不足時提示。門檻屬取樣保護，沒有用來宣稱裝置視力測量精度。例：5 CSS px/mm 的 1× 桌機與 3× 手機，0 logMAR 缺口分別約 0.58 與 1.75 render px，均未達 2 px。3× 手機的 0.1 logMAR 缺口約 2.20 px，可供初步量測。

## 試行流程與匯出

1. 校正信用卡短邊，填匿名代碼。固定 40 cm、平常適合此距離的矯正、裝置亮度、環境與縮放。
2. 在 σ=0 時確認能重複辨識的最小 C，按 **Set unblurred baseline**。更小的 C 可檢視，不能記錄為有效模糊閾值。
3. 從較大 C 開始，改變方向複查。按 **Mark readable** 記最後可辨識值，增加 σ 後按 **Mark unreadable** 記首次無法辨識值。只有正確排序的上下界可存。**Record threshold** 在同級重測，**Record & next size** 存檔並縮小一級。到基線或取樣下限即停止。
4. 結果表列出級別、重複次數和 σ 範圍。CSV 與 JSON 記匿名 ID、裝置、校正資料、觀看距離、光柵比例、時間、基線及刺激 logMAR，還有上下界的 arcmin 與 render px。量測保留在目前頁面，請於離開前匯出。

## 與主模擬器的銜接

臨床曲線是絕對視力。校準結果的劣化量定義為刺激 logMAR 減去同一受試者的未模糊 baseline logMAR。將來可用同一顯示與矯正條件的重測資料，擬合帶區間上下界的 σ 對劣化量關係，再用明確指定的觀察者基線，把臨床絕對 VA 轉成等效劣化。主模擬器已把暫定的參考像素公式轉為 angular σ，未來可在 `provisionalSigmaArcmin` 這個轉換點換入驗證後的曲線。

兩頁共用 σ 單位、顯示尺度與離散 Gaussian 權重定義。WebGL 保留既有的線性插值合併相鄰權重、0.05 texel 量化及大 σ 多次卷積，校準頁在原生取樣網格直接卷積。正式擬合前應核對實際顯示的對比、螢幕亮度響應與 WebGL 取樣偏差。此頁採自報門檻，沒有強迫選擇、盲化或階梯法。未導入智慧眼鏡係數，也未將試跑資料作為新臨床映射。

## 驗證

Chromium 和 WebKit 的手機模擬均完成信用卡校正、未模糊基線、低解析度限制、重複閾值與縮小一級，並讀回 CSV、JSON 中的角分及像素。三款鏡片可各自載入曲線，超出實測 defocus 時只遮蔽相應欄位。兩個引擎也通過強制 CPU 路徑及九組 WebGL2／CPU／Python 影像驗證，最大差為 1 個 sRGB 量化階。iPhone 實機顯示取樣與主觀閾值仍待驗收。

Physics-based 暖快取與 Phase 12 末版以 390 × 844 CSS px、3× DPR 重播。40 cm 條件下輸入到畫面提交的 p95，單畫面前後均為 8.6 ms，分割由 7.9 ms 至 7.3 ms。100 cm 及 20 cm 的其他重播仍走暖快取 WebGL2。首次拜訪的預取偶有落空，取決於輸入和資產解碼完成的先後，測得新版那次約 28 ms。
