# Phase 9A CPU 渲染優化

Physics 雙眼比較以完整場景的取樣網格定位背景和字卡。Worker 依 `floor(width / 2)` 分配左右可見區，直接寫入同一個 RGBA 緩衝區，再一次交給 WebGL。預計算路徑只積分可見像素所需的來源欄位。Dynamic FFT 的來源保留完整 PSF 支撐所需的邊帶，背景只在整個場景的外緣反射。FFT 僅擷取可見輸出，尺寸依所保留的線性卷積範圍決定。

光學 PNG 維持原有密度與完整像素驗證。雙眼只將可見欄位及取樣邊界所需的來源像素留在 Worker。已有涵蓋該區的快取時，Worker 直接取出所需欄位。需要重新載入時，驗證完整 PNG 後才裁切並轉移所有權。大型解碼依原有的 14 MiB 緩衝預算分批執行，Worker 的光學 LRU 也維持 14 MiB。在下列高密度條件下，兩眼各兩個相鄰節點的工作集從 25.21 MiB 降為 3.67 MiB。下載或驗證失敗，以及超出預算或驗證密度範圍的畫面仍沿用 dynamic FFT。

## 效能

Phase 8 基準為 `3fc6686`。同一台 Windows 桌機以 Chrome 156 執行 production build，模擬 390 × 844 CSS viewport、DPR 3 與觸控。暖機後量測 slider input 到相符畫面提交，包含 Worker 與 WebGL。一般組為 40 cm、6.693 CSS px/mm，循環 2.4–2.6 D。高密度組為 100 cm、7.781 CSS px/mm，往返 3.9 與 4.0 D。每組連續輸入派發 23 筆，間隔 16.67 ms，延遲從最後一筆計算。

| 情境 | 樣本 | Phase 8 median / p95 | Phase 9A median / p95 |
| --- | ---: | ---: | ---: |
| Aspheric 單眼 | 30 | 10.1 / 11.8 ms | 11.3 / 12.3 ms |
| Spherical 單眼 | 30 | 11.0 / 11.9 ms | 10.3 / 12.2 ms |
| Vivity-like 單眼 | 30 | 10.8 / 12.6 ms | 10.3 / 11.8 ms |
| Aspheric + Vivity-like 雙眼 | 30 | 20.1 / 22.1 ms | 9.5 / 10.6 ms |
| 一般雙眼連續輸入 | 8 組 | 20.9 / 27.3 ms | 9.6 / 11.2 ms |
| 高密度雙眼 | 16 | 95.2 / 102.7 ms | 10.5 / 11.7 ms |
| 高密度雙眼連續輸入 | 6 組 | 112.0 / 157.2 ms | 10.3 / 10.8 ms |

一般雙眼單次 Worker 輸出由 1,937,520 bytes 降至 968,760 bytes，高密度由 611,448 降至 305,724 bytes。高密度連續輸入六組共提交 113 個畫面，Phase 8 提交 6 個。高密度暖機往返 16 次時，兩眼使用預計算影像，期間沒有光學 PNG 重新下載、Canvas 讀回或 Worker 影像註冊。

## 數值與功能驗證

- 三組鏡片配對在 1.0、2.5、4.0 D 的一般雙眼畫面逐位元組符合 Phase 8。高密度以 Phase 8 全幅預計算作為對照，3.9、4.0 D 也逐位元組一致。對照用的 Phase 8 本機測試暫時放寬快取，讓兩眼同時使用全幅影像。
- 在高密度刻意讓 Vivity PNG 無法下載時，裁切 FFT 和 Phase 8 全幅 FFT 輸出逐位元組一致。兩個節點的近景 FFT 由約 69–76 ms 降至 16–18 ms。Phase 8 正式版在此條件一眼走 dynamic，與 9A 雙眼預計算的最大差為 2 個 sRGB byte。以獨立 SciPy 16384 取樣參考驗證兩眼預計算的可見區及四種背景亮度，最大 linear RMSE 為 0.000185，最大 sRGB 差為 1 byte。
- 54 項測試涵蓋 PSF 能量、不同 X/Y 取樣密度、全部 170 張光學 PNG、奇偶寬度分界及支撐跨界的非對稱 PSF。瀏覽器驗證頁通過 Python、Worker 與 WebGL 比對。功能驗證涵蓋三種 IOL 在 100 cm 的 93 個節點、相同與不同鏡片比較、Gaussian 往返、校正、觸控拖曳、背景重試及 Worker 恢復。

瀏覽器數字包含提交畫面前的時間，實機螢幕延遲、iPhone Safari 的記憶體與冷啟動仍待手機驗收。新取得的光學影像仍需下載、解碼與驗證完整 PNG，dynamic FFT 首次計算也仍會占用 Worker。
